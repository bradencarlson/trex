Documentation

Project Setup

Before using TreX, it is necessary to have your project set up properly. TreX takes separate files, each listed in the configuration file, and options passed via the command line, and creates a compile command that is to be run.

If your project is such that every file is to be included every time you wish to compile, setting up your project for use with TreX is probably already done.

If your project contains many pieces, of which you wish to compile a subset at a time (i.e. lecture notes, chapters of a book, etc.), Then there is some preliminary work you must do to ensure that TreX can succesfully compile your project.

The preamble of the document must be contained in it's own file. There must not be any \begin{document} or \end{document} commands in any file, since TreX will insert these where needed. Also, since there is the option to specify sections or chapters in the config file, it is recommended to either specify all sections or chapters in the config file, or none of them. In the latter case, simply specify each section in the project files like normal. See the example for a demonstration of the first method.

Configuration

All configuration for TreX is done through a simple file located in the root directory of your project. The default config file name is trex.conf. Other config files can be used by specifying the -f option, documented below.

The content of the config file is a sequence of key value pairs of the form key: value. Notice that there is no space before the semicolon, but there is one afterwards. This is the only spacing which is important in the config file, any white space at the beginning or end of a line will be ignored.

Any line in the config file starting with a # is a comment and will not be parsed by TreX.

Key Value Pairs

class This key is required, and simply specifies the document class of the file. For example, the value could be article, book, etc.
preamble This key is required, and specifies the filename of the preamble for the document.
handle_chapters This optional key specifies whether or not TreX should handle chapter commands or not. Valid values are 'true' or 'false'. The default is 'true'. If this value is set to 'false', TreX will still keep track of and set chapter numbering according to the chapter commands that it finds in the config file, but will not insert any \chapter{} commands when it goes to compile. If you do not wish for Trex to even keep track of chapter commands, simply do not put any chapter commands in the config file.
handle_sections See handle_chapters.
handle_subsections This optional key specifies whether or not TreX should handle subsection numbering or not. Valid values are 'true' or 'false'. The default is 'false'. If this value is set to 'true', TreX assumes that each file specified in the config file is a separate subsection, and subsection numbers are set accordingly.
chapter This key may appear multiple times in the config document, and each specifies a new chapter in the document. The value should be the intended chapter name.
section See chapter.
file This key may appear multiple times in the config file, and specifies a file to be included in the document. The value should be the filename of the file to be included.
bib_style Defines the style of the biliography. This value should be the value you wish to pass to \bibliographystyle in LaTeX.
bibliography The file where bibliography entries are stored.

Example Config

Below is an example config file from a series of lecture notes.

class: article
preamble: preamble.tex
handle_subsections: true
section: Linear Equations and Row Reduction
 file: lecture-1.tex
 file: lecture-2.tex
 file: lecture-3.tex
 file: lecture-4.tex
section: Matrices and Matrix Algebra
 file: lecture-5.tex
 file: lecture-6.tex
 file: lecture-7.tex
section: Determinants
 file: lecture-8.tex
 file: lecture-9.tex
 file: lecture-10.tex

With the configuration setup in this way, running the command

trex -r 2 -j filename

will create the file filename.pdf with the contents of lecture 2, properly setting the section numbering to 1.2. The way this is done is by calling pdflatex with the following content:

\documentclass{article}
\input{preamble.tex}
\begin{document}
\setcounter{section}{0}
\section{Linear Equations and Row Reduction}
\setcounter{subsection}{1} \input{lecture-2.tex}
\end{document}

Please note that the command line option -r 2 specifies to select the file contents of the second file listed in the config file, and does not have anything to do with the file name.

Command Line Options

-c Clean up auxiliary files from compiling, if any. Currently, if no engine is passed to TreX, nothing will be done.
-d Dry run option. Instead of compiling the document, print out the command that would be run.
-e The engine to use when compiling. Currently the only engine available is pdflatex. This option should not currently be used.
-f The config file to use. If you do not wish to use the default config file, specify the location of the config file with this option.
-j The jobname. This specifies the filename of the compiled document. For example, to specify that the output file should be named exam-1.pdf, use -j exam-1. The default is "out".
-o Pass options to the compiler. For example, to pass the 12pt option to the article class, use -o 12pt and use class: article in the config file.
-r The range of files to include when compiling. See the range specification section for more details.
-v Verbose output. This will force TreX to print out what it finds in the config file, as well as the command that it will run.

Range Specification

When using the -r option. The value must be exactly one of the valid range specifications found in the following table.

Range If N is the total number of times the file keyword appears in the config file, then any subset of {1,2,...,N} specifies exactly which files to include. For example, to include only the third file listed in the config, use -r 3. Other valid ranges include -r 1-3, -r 3-5,7-9, and -r 3,5,9-11.
Chapter/section name Any chapter or section name as specified in the config file. For example -r "Chapter 2".
Chapter number If N is the total number of times that the chapter keyword appears in the file, then the range -r cn, where n is a number between 1 and N, selects all files belonging to the nth chapter listed in the config file.
Chapter/section number If there are both chapter and section commands in the config file, you may select a particular section of a particular chapter by using the range -r cnsm, where n specifies to use the nth chapter and m the mth section in that chapter. For example, to compile section 2 of chapter 3, use -r c3s2.
Section number If N is the total number of times the section keyword appears in the config file, then the range -r sn, where n is a number between 1 and N, selects all files belonging to the nth section listed in the config file. Note that if there are chapter commands listed in the config file, this may not work as expected. If this is the case, it is recommended to use a chapter/section number instead.
All By using the range -r all, all files are selected for compiliation.
